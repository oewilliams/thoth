# Cycle 014 — arena (one buffer, emitted once, checksummed as it goes)

Supersedes cycle 013 (fused emit), which does not run: 012's gate
priced each fusion separately on speed alone, and the scratch
prototype (`/tmp/thoth-arena`, safe Rust, byte-identical output)
showed the two fusions only pay as one layout change. This cycle is
that change, justified on layout and memory with speed as a
constraint — not on any per-fusion percentage.

Depends on 011 (multi-sheet API) and 012 (phase table) reviewed by
the human and committed. No work starts on the uncommitted
011–012 stack.

## Design locks recorded before this spec

- **One residency.** Generated bytes are written once, into the
  buffer that is returned (or written to disk). Intermediate
  per-sheet buffers, a staged entry list owning `Vec`s, and an
  assembly copy do not exist on the build path. The floor is one
  emission write plus the kernel copy in the file write; every
  other residency must justify itself.
- **Templates hint size; correctness never depends on the hint.**
  A template declares either a size hint derived from a known
  shape, or which dimension (rows, columns) is unknown — and
  which case holds is known exactly at the boundary, before
  emission. Known shape: one reservation, no realloc. Unknown
  dimension: the same builder growing in blocks (an occasional
  tail copy), chosen up front per template, never discovered
  mid-emission. Byte output is identical either way.
- **Zip is internal.** `ZipWriter` was never a user surface; it is
  retired as a public type and the archive builder is the single
  internal spelling. CRC spellings survive only as internal
  machinery (benches re-point or measure in context).
- **The checksum stays.** It is the ZIP format's field, verified
  by readers; it is folded per row so bytes are read while hot,
  not removed.

## Background

At 011 a sheet's bytes are touched at least four times: emission
into a per-sheet `String` (`src/xlsx.rs` `sheet_xml`), a CRC pass
(`ZipWriter::add`), an assembly copy (`ZipWriter::finish`), and
the kernel copy (`fs::write`). 012 priced removing passes two and
three at 2–3% (copy) and 8–14% (CRC) of end-to-end and gated both
out. The prototype then combined them with a byte sink and
measured, build-only at 200k rows on agreeing reads: ints
~8.5% faster, floats ~7.7%, nulls ~2–3%, and peak RSS on a 200k
mixed build falling from 39.0 MB to 22.1 MB — the double
residency gone. Its byte emitter was deliberately untuned and
lost to the `String` emitter on ints and nulls, so the prototype
numbers are a floor for the shape, not its tuned result.

## Prototype rounds (scratch evidence, `/tmp/thoth-r1`)

Alternatives were raced in an interleaved A/B harness (rotating
order, medians of rounds; sequential Criterion runs on this box
drifted enough to flip verdicts, and are not evidence here):

- **Reservation:** hint-sized and upper-bound reservations tie on
  time (within 0.2%); growth from empty loses the arena's whole
  advantage (parity with the current path). Retained capacity at
  200k mixed rows: exact 16.9 MB (current), hint 20.2 MB,
  upper-bound 84.8 MB for the same 16.9 MB archive. The hint is
  therefore the reservation; the upper bound remains a proof, and
  growth is the unknown-dimension fallback, priced as parity.
- **CRC granularity:** per-row folding beats whole-sheet
  (ints 4.43 vs 4.93 ms) and 64 KB chunks (5.00 ms) at 200k on
  every recipe. Per-row it is.
- **Byte emitter:** a tuned byte spelling is at parity with the
  `String` oracle (ints/nulls ~2% slower, floats ~3% faster,
  interleaved medians) — the arena's win comes from layout and
  folding, not emitter superiority. R4's parity bar stands.
- **Combined winners** (hint + per-row fold + tuned bytes),
  build-only at 200k vs current: ints ~11% faster, floats ~9%,
  nulls ~3%; peak RSS 39.1 MB -> 22.1 MB, repeated.

## Requirements (each item testable)

- **R1 — Arena builder.** `build_workbook` emits into one buffer:
  per entry a reserved 30-byte local header plus name, the part's
  bytes emitted directly after it, then CRC (R3) and the equal
  stored sizes patched at header offsets +14/+18/+22. Entries are
  held as `(name, crc, len, offset)` records, never owning data
  buffers. The central directory and end record append after the
  last entry. Static fragments and the RELS/STYLES constants
  append in place (their one unavoidable copy). `sheet_xml`
  remains the standalone oracle spelling; archive bytes are
  identical to the 011 output on every recipe, pinned by the
  existing golden/cat-identity/verbatim-embed tests unmodified.
- **R2 — Reservation follows the template declaration.** The
  reservation for each sheet comes from the template's size hint
  when the shape is known, and from block growth when a dimension
  is declared unknown. `sheet_cap` survives as the worst-case
  proof bound (and its tests), not as the reservation. Returned
  buffer capacity versus length is measured and recorded; a
  caller must not silently retain a several-times-length
  allocation without this spec's successor deciding that is
  acceptable.
- **R3 — CRC folded per row.** A chunked-update CRC spelling
  beside `crc32` (any split equals the one-shot result, pinned by
  unit tests including empty chunks). On the build path each
  sheet's CRC updates once per emitted row over that row's range
  in the arena; no whole-sheet `crc32` call survives on that
  path. Small parts checksum their just-emitted range.
- **R4 — Byte sink, tuned to parity.** Cell emitters write bytes
  into the arena (fragments as byte constants, digits from
  `DEC_PAIRS`, the `f64` spelling byte-identical over the
  cycle-007 probe set). Acceptance includes emission parity:
  the byte emitter must not regress `sheet_xml`-oracle emission
  times on ints or nulls beyond noise on agreeing reads — the
  prototype's known deficit is this cycle's work, not its
  inheritance.
- **R5 — Zip32 ceiling re-derived.** `archive_fits` continues to
  run; every narrowing cast on the arena path is re-listed cast
  for cast against a check that covers it (actual emitted
  lengths where known, conservative projection only where named
  with its reason). Existing ceiling tests green; the 011
  many-sheet test green.
- **R6 — Measured acceptance, reframed.** Post-014 `TESTING.md`
  entry re-takes the 012 phase recipes on agreeing reads and
  records: (a) byte-identity held; (b) peak-memory probe (012 R4
  method) shows single residency; (c) build time per recipe
  against the Post-012 table — no recipe regressing beyond
  noise, the combined gain in or above the prototype's range
  (ints ~8.5%, floats ~7.7%, nulls ~2–3% build-only) expected
  but treated as a report, not a gate. A regression beyond
  noise on any recipe blocks shipping until explained.

## Scoped files

`src/emit.rs` (byte sink), `src/zip.rs` (CRC update; `ZipWriter`
retired, archive machinery internal), `src/xlsx.rs` (arena
`build_workbook`, backpatch, ceiling, `sheet_xml` as oracle
wrapper), `TESTING.md` (Post-014 entry), `DESIGN.md` (Floor and
Templates wording updated by the applicator to the locks above),
`specs/014-arena/` records by role. Untouched: `src/static_parts.rs`,
`src/contract.rs`, `tests/` (a test needing an edit is a finding),
`examples/`, manifests. No new dependencies, no new public API.

## Boundaries (not this cycle)

- No direct-to-file streaming, no `unsafe` cursor: the safe
  spelling ships first; `unsafe` enters only behind a later
  measurement naming what it buys (cycle-004 precedent).
- No deflate, widths, freeze panes, number formats, string or
  bool columns: later cycles, now emitting through the arena.
- Error and sealed-write semantics exactly as 011 left them:
  refusals abort before any file exists.

## Workflow (on `go`)

Producer, reviewer, applicator as three independent agents, one
role each, per `specs/README.md`; the producer's brief adds the
prototype location (`/tmp/thoth-arena`) as evidence, not as code
to copy. Everything left uncommitted.
